## 输入原则

最低外部输入包括初始目标、已知范围、禁止或暂停边界、期望交付物和已知验收
要求。源实现位置可以由用户提供，但 Skill 必须自行验证，不能把路径存在等同于
它是有效实现。

技术事实应从 workspace、代码、历史、文档、配置、构建/链接选择、二进制资产
和既有证据中发现。目标、范围、成本、验收和风险接受属于用户决策。

## 门禁定义

| 门禁 | 通过条件 | 未通过时的有效输出 |
|---|---|---|
| G0 输入契约 | 目标、范围、边界、交付物、验收对象、`work_root` 和任务名已确认 | 一次询问一个最高优先级缺口 |
| G1 基线 | 观察、历史、拟交付基线已分离；相关 repo、配置、工具、资产和硬件身份可复核 | 基线冻结或证据采集项 |
| G2 源设计 | 有源时已解释有效行为、历史、顺序、不变量和失败；无源时有证据地标为不适用 | research、prototype 或源身份核实项 |
| G3 目标契约 | OpenVela 公共入口、调用链、执行 context、资源所有权和固定规范已确认 | 目标规范研究或冲突决策 |
| G4 设计闭包 | 四类职责、处置矩阵、严格阶段图、执行契约和外部兼容单元均闭合 | 设计缺口或用户取舍 |
| G5 验证设计 | 每项结论都有风险推导的最低证据、有效性、失败判据和回退入口 | 验证设计或可证伪性缺口 |
| G6 冻结复审 | 双向完整性检查通过，阻断未知项清零，人工决策确认，Map 可执行且可验收 | 当前事实、残留缺口和下一调查项 |

G2 只有在用户明确声明原生新功能无源，或已锁定源基线并对相关模块、配置、
历史和同义行为完成有范围的检索、能够排除隐藏/改名实现时，才可为
`not-applicable`。不确定时保持 `source-mode: unknown` 并阻断依赖分支。其他
门禁不能因任务规模小而省略；可以缩小内容，但必须给出通过依据。

## 未知项和暂停规则

以下未知项会推翻总体设计，必须标成 `blocked` 并转为独立调查：

- 职责归属、公共入口或执行阶段不明确。
- 接口/ABI、预编译库、firmware header、镜像或工具兼容关系不明确。
- clock、memory/cache、flash、PMP、IRQ 等关键时序或硬件不变量不明确。
- 安全边界、失败/降级/恢复策略或验收方法不明确。
- dirty/floating baseline 可能改变设计结论。

只影响局部实现、不会改变总体方案的未知项可以进入 Map，但必须绑定验证条件、
失败判据和重新设计入口。无法判级时按阻断项处理。

阻断按依赖传播，不默认停止整个 Skill。将依赖该未知项的分支标为 `blocked`，
继续无依赖的安全发现；只有剩余工作全部依赖阻断项，或下一步需要用户决策、
额外权限时才整体暂停。任一阻断项未解决前不得冻结设计和 Map。

顶层 `Knowledge state` 只使用：

- `gathering`：仍有安全、独立的信息发现可以继续，允许局部分支阻断。
- `blocked`：没有可独立推进的工作，必须等待用户、权限、基线、证据或 reviewer。
- `ready-for-handoff`：G0-G6 均满足，Design 和 Map 已冻结。

执行反馈推翻设计时从 `ready-for-handoff` 回到 `gathering` 并重开受影响门禁，
不要增加“基本完成”或“大致可用”等模糊状态。

## 人工确认边界

以下内容不能由 Skill 自动决定：

- 扩大或缩小能力范围。
- 省略、延期或改变源端有效行为。
- 改变 ABI、外部产物格式或工具兼容性。
- 在多个有效架构方案之间取舍。
- 改变失败、降级、恢复或安全策略。
- 接受缺少运行证据的残留风险。

每次只提出一个决策问题，先说明事实、受影响契约、可选项、推荐项和理由。

## 最终复审

涉及严格时序、linker/镜像、ABI/预编译库、烧录/产测、安全边界，或具有高
后果、高不确定性、跨多个边界特征时，冻结前必须由未参与主设计的 reviewer
复审。reviewer 从工作包、源码和原始证据重建判断，不只阅读设计结论；当前没有
reviewer 时 G6 保持 `blocked`。低风险且公共契约唯一的局部任务可以使用一次
结构化冷启动复审轮次，不强制第二个人或 subagent。

冻结前至少检查：

1. 每个声明能力都能从目标追到设计、Map 和验收证据。
2. 每项相关源行为或资产都有唯一处置；省略/延期有影响和重新进入条件。
3. 没有空 hook、占位结构、无调用 wrapper 或重复 provider。
4. 启动、链接、镜像、ABI 和工具链没有被 compile-only 结论覆盖。
5. 失败语义和早期不可观察阶段有明确设计。
6. 旧证据只在 fingerprint 未发生影响性变化时复用。
7. 新发现的矩阵外影响项已经重新打开设计，而不是直接加入实现。
