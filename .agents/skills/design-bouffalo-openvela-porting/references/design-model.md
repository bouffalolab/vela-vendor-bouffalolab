## 四类职责

1. **芯片硬件不变量**：寄存器值、上电顺序、clock、memory/cache、PMP、flash、
   section load 等步骤依赖和副作用。目标结构可以不同，但语义、顺序和不变量
   必须保留。
2. **OpenVela 执行契约**：IRQ、serial、timer、heap、driver registration、
   调用 context、并发和错误接口。OpenVela 决定入口、所有权、命名和结构，
   源 SDK 只提供必要芯片约束。
3. **跨边界产物契约**：ABI、预编译库、firmware header、section/镜像布局、
   postprocess、烧录和产测输入。OpenVela 可以改变生成方式，不能静默改变消费
   工具看到的格式和语义。
4. **任务策略**：本阶段能力、允许降级、资源分配和验收范围。只能来自已确认
   目标和用户决策，不能从 SDK 默认配置或模板反推。

一个源函数包含多种职责时必须拆开，不能写成“双方共同负责”。

## 职责矩阵

每项行为或资产至少记录：

- 唯一 ID、行为/资产和职责类别。
- 源依据；无源任务使用已确认需求依据。
- 必须保持的顺序、硬件不变量或外部格式。
- OpenVela 目标职责、公共入口和实际调用条件。
- `复用 / 适配 / 替换 / 省略 / 延期` 的唯一处置。
- 理由、依赖、失败语义和重新进入条件。
- 风险、验证方式、预期证据和失败回退入口。

从源有效调用链、条件编译、source list、linker、生成脚本、二进制资产、回调和
失败路径正向检查；再从任务能力及 OpenVela 公共入口反向检查。只有职责、理由
和验证完全相同的项才能合并。

## 严格阶段与约束图

对每个严格阶段记录：

- 前置条件、完成保证以及必须先于/晚于的阶段。
- BootROM/boot2 后、cache 前后、XIP/RAM、scheduler 前后和 IRQ 状态。
- 使用的 memory、clock、stack、寄存器和外部资产。
- 失败是阻断、降级还是延后报告。
- 能证明其正确的 source、ELF、镜像或运行证据。

追踪对象是步骤、依赖和不变量，不是文件名或函数名。

## OpenVela 执行契约

每项目标职责记录：

- 实际调用链、触发条件和调用频率。
- 线程、中断或 scheduler 尚未启动的执行 context。
- 是否允许阻塞、睡眠、分配内存或使用锁。
- 可重入性、并发、同步、幂等、重试和恢复要求。
- IRQ、cache、clock 和 heap 等调用前状态。
- 返回值、错误传播、记录和降级语义。

从目标公共入口和调用者反推文件与模块。wrapper 只有在转换 ABI、编号、context
或错误语义时成立，单次转调本身不构成独立模块理由。

## 跨边界产物契约

把源格式定义、生成工具和消费工具作为同一版本组合，记录：

- 字节布局、地址、alignment、CRC/hash/signature 和 section。
- 工具链、ISA/ABI、compile definitions、公开头和实际链接符号。
- boot2、postprocessor、烧录和产测消费者；任务明确涉及 Flash 实际字节时再
  纳入 readback 消费者。
- 二进制对比、真实 parser、map/ELF 和烧录证据要求；readback 不是默认门禁。

改变格式或 ABI 时，所有消费者必须进入同一显式迁移任务，否则属于阻断项。

## 证据层

| 层 | 证明范围 | 不能替代 |
|---|---|---|
| V0 基线与有效性 | 精确代码、配置、工具、资产、硬件和环境组合 | 实现正确性 |
| V1 源码与确定性契约 | 结构、接口、配置依赖、静态规则和局部语义 | 构建选择、板上行为 |
| V2 clean build | 当前组合可构建以及实际 source/宏/generated input | provider、布局、运行 |
| V3 ELF/map/ABI/机器码 | provider、VMA/LMA、entry、section、ABI 和关键机器码 | postprocess、硬件结果 |
| V4 镜像与工具兼容 | header、offset、partition、签名及真实消费者解析 | flash 中字节、运行 |
| V5 烧录身份与复位传输 | 选定 artifact、目标设备、地址/分区、烧录结果和复位链路 | Flash 实际字节、启动后的系统行为 |
| V6 启动链与基础可观察性 | 指定接口、baud、artifact 身份、marker 和最小往返 | 任务全部功能 |
| V7 功能、context 与异常路径 | 公共入口、并发、重入、错误、恢复和故障场景 | 长期稳定性 |
| V8 重复、稳定性与回归 | 非确定性、跨周期、压力、升级/回退和长期风险 | 未覆盖的能力 |

层级不是成熟度分数，高层不能替代低层。为具体结论选择能使其被证伪的最小
集合，并说明未选择其他层的理由。

readback 仅用于任务明确要求证明 Flash 实际字节、擦除区或产测内容的专项场景；
普通移植、构建、烧录和启动验收不因工具缺少 readback 而阻断。

## 风险推导

对每个结论取下列触发器要求证据的并集：

- 后果：不开机、错误执行、数据破坏、安全、ABI/镜像不兼容或量产失败。
- 不确定性：新芯片、新工具链、新源版本、手工重写或预编译黑盒。
- 边界跨度：跨 source/config/link/image/boot2/tool/device/subsystem。
- 目标依赖：真实寄存器、IRQ、cache、clock、flash、RF、电源或 scheduler。
- 历史复发：错误 provider、地址、旧镜像、错误 baud 或无效 run。

高后果、高不确定性或跨多个边界的结论至少需要直接消费者证据和独立复审；
存在非确定性时增加 V8。

## 状态语义

- `not-applicable`：有职责和风险依据证明不需要。
- `not-run`：拟交付基线上未执行。
- `blocked`：缺少输入、工具、设备或前置决策。
- `invalid-run`：执行过但 artifact、配置、设备、环境或时长不满足有效性。
- `failed`：运行有效但不满足验收条件。
- `layer-passed`：指定结论在指定证据层通过。
- `partially-passed`：只完成必需集合的一部分，必须列出缺口。
- `risk-accepted`：用户接受证据缺失，不等于通过。
- `fully-accepted`：全部必需结论和证据有效通过，复审、重复和残留风险已处置。
