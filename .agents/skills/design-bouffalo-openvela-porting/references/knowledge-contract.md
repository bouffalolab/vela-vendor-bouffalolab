## 唯一知识源

所有由本 Skill 产生的工程知识先统一保存到：

```text
<work_root>/.porting/<task-name>/
├── BASELINE.md
├── STATUS.md
├── JOURNAL.md
├── DECISIONS.md
├── DESIGN.md
├── MAP.md
└── evidence/
    └── INDEX.md
```

`work_root` 由任务上下文提供或经用户确认。默认不发布、不加入 Git、不修改
`.gitignore`。一个工作包对应一次明确目标和一组冻结基线。

核心文件和必查语义固定，任务可以增加适合自身的章节、矩阵或图。某类契约
不适用时保留检查项并写明排除依据，不能删除检查项或留下空白占位；冻结包必须
清除“尚未确认”“当前没有”等初始化状态文本。

## 文件职责

- `BASELINE.md`：当前目标、范围、明确排除、冻结基线、芯片约束、适用规范和
  经证据确认的事实；不保存设计或进度。
- `STATUS.md`：信息、设计和 Map 的知识成熟度、阻断缺口和下一知识动作；不是
  实施任务状态。
- `JOURNAL.md`：只追加事实、设计、Map、证据和门禁的变化；不复制普通命令
  流水、完整对话或实施进度。
- `DECISIONS.md`：关键取舍、适用范围、依据、被拒方案和替代关系。
- `DESIGN.md`：当前有效的职责映射、阶段约束、执行契约、外部兼容、风险和验证
  设计。历史由 Decisions 和 Journal 保留。
- `MAP.md`：执行阶段的工作项、依赖、边界、风险、完成条件和证据要求；不是
  实时任务看板。
- `evidence/INDEX.md`：结论与证据身份、采集方式、有效性、位置、哈希和保留
  状态的索引。

术语存在真实歧义时可以增加 `GLOSSARY.md`。不要创建 `CONTEXT.md` 保存设计或
基线，避免与将其定义为纯术语表的其他 Skill 冲突。

## 证据规则

- branch、dirty state、工具/设备状态和临时路径等易漂移事实只作为带时间的
  观察快照，不写成长期事实。
- 文本、关键日志、分析结果和小产物直接放入 `evidence/`。
- 大型或可重建产物可以外置，但索引必须保存精确位置、版本/hash、获取方式、
  有效性和保留状态。
- 不可重建、可能消失且支撑关键结论的证据必须复制入包。
- 外置证据失效时，依赖结论不能继续标为已确认。

## 变更与纠错

- `JOURNAL.md` 只追加。错误结论通过新记录和失效声明纠正，不改写历史。
- 已确认决策正文不改写；新增决策并把旧项标为 `superseded`。
- `DESIGN.md` 保存当前有效答案，可以随有效决策更新。
- Map 冻结后改变设计，先形成决策并记录 Journal，再更新 Map。
- 冻结后改变实际 source/target baseline 时创建新工作包；只纠正误记身份时留在
  原包，但重跑所有受影响门禁。

## 外部系统

Jira、Wayfinder、`long-task-workflow` 或其他任务系统只引用工作包并保存自己的
协调元数据。若同时调用的 Skill 要求在其他位置保存同一份稳定知识，必须在写入
前报告契约冲突并让用户选择；禁止静默双写或根据本机环境自动选择权威源。

执行进度、人员和排期留在外部任务系统；执行证据继续登记到工作包。符合冻结
设计的证据只追加 Index 和 Journal。若执行暴露基线漂移、职责遗漏、错误假设或
Map 外影响项，必须重新显式调用本 Skill 并打开受影响门禁；外部执行流程不能
自行改写冻结的 Design 或 Map。
